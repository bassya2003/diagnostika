# Сессия 4. Техническая архитектура платформы Sana Space

**Версия 1.0 — на валидацию.** Все продуктовые решения предыдущих сессий учтены как требования: гибридная модель, диагностика по дням, приватный чат, safety-флаги только консультанту, голосовой ввод, двуязычие, треки ЕНТ/зарубеж.

---

## 1. Роли и доступы (основа всей архитектуры)

| Роль | Видит | НЕ видит |
|---|---|---|
| **Подросток** | Свои задания, свой чат с ИИ, свой опубликованный отчет | Черновик отчета, флаги, сырые баллы до публикации |
| **Родитель** (B2C-плательщик) | Статус прохождения (день Х из 7), финальный отчет | Переписку ребенка с ИИ, сырые данные |
| **Консультант** (вы / кураторы) | Всё: профиль, переписку, черновик отчета, флаги (safety — красным, немедленно) | — |
| **Школа-админ** (B2B) | Список учеников и прогресс, агрегированную аналитику класса, финальные отчеты (в объеме, разрешенном родителем) | Переписку, индивидуальные safety-флаги |
| **Супер-админ** (Sana Space) | Управление контентом, тарифами, франчайзи-консультантами, версиями промптов | — |

Ключевое техническое следствие: чат-логи шифруются, права доступа проверяются на уровне API (не интерфейса), каждый доступ консультанта к переписке пишется в audit log.

## 2. Общая схема

```
Подросток (web, mobile-first PWA)
   │  RU/KZ интерфейс, голосовой ввод
   ▼
Frontend: Next.js (React) + i18n — сайт, тест-движок, чат
   ▼
Backend API: Python FastAPI (или Node/NestJS — по команде разработки)
   ├── Auth-сервис: телефон+SMS, согласие родителя, роли
   ├── Движок программы: календарь дней, доступность заданий, напоминания (WhatsApp/push)
   ├── Диагностический движок: свайпы, опросники, игра → скоринг → JSONB-профиль
   ├── ИИ-оркестратор: системный промпт + mode + profile_json → Claude API
   │     ├── этап 1: диалог (стриминг)
   │     └── этап 2: экстракция JSON дня (отдельный вызов)
   ├── STT-сервис: голос → текст (KZ+RU)
   ├── Отчетный модуль: report_draft → кабинет консультанта → публикация → PDF
   └── Биллинг: Kaspi Pay (B2C), инвойсы и лицензии (B2B)
   ▼
PostgreSQL (данные) + S3-совместимое хранилище (аудио, PDF) + Redis (сессии, очереди)
Хостинг: серверы на территории РК (требование закона о персональных данных)
```

## 3. Схема данных (ядро)

```
users(id, role, phone, lang, birth_date, city, ...)
guardians(user_id → teen_id, consent_signed_at, consent_doc)
orgs(id, name, type=school, contract, seats_total, seats_used)
classes(id, org_id, grade, consultant_id)
enrollments(teen_id, class_id | b2c_order_id, track: kz|abroad|both|undecided, constraints jsonb, voluntary bool)
program_days(enrollment_id, day_no, status, opened_at, completed_at)
day_results(enrollment_id, day_no, raw jsonb, scored jsonb, confidence, contradiction_flag)
profiles(enrollment_id, merged jsonb)          -- накопленный JSON-профиль
chat_messages(enrollment_id, day_no, role, text_encrypted, audio_ref, created_at)
reports(enrollment_id, draft jsonb, status: draft|approved|published, consultant_id, approved_at, pdf_ref)
flags(enrollment_id, type: safety|selfdoubt|money_unrealistic|low_confidence|involuntary, payload, seen_by, created_at)
content_library(key, lang, type: question|interpretation|scene|ui, version, text)   -- весь контент версионируется
prompt_versions(id, text, active_from)          -- промпт тоже версионируется
audit_log(actor_id, action, object, ts)
```

Принцип: весь диагностический контент (вопросы, интерпретации, сцены игры) — в `content_library`, а не в коде. Вы сможете править формулировки и добавлять языки без разработчика.

## 4. Кабинет школы (B2B)

- **Лицензии:** школа покупает пакет мест (seats). Активация — кодом класса или списком учеников. Дашборд: использовано/осталось.
- **Прогресс:** таблица учеников — день программы, статус, дата завершения. Без содержания ответов.
- **Агрегированная аналитика класса** (это отдельная продаваемая ценность для школы): распределение векторов RIASEC по классу, топ ценностей поколения, % зоны компромисса («в классе 11 детей отказались от профессий из-за неверия в себя») — все агрегаты анонимизированы, минимум 8 учеников для показа (защита от деанонимизации).
- **Отчеты:** доступ к финальным отчетам учеников — только при согласии родителя (галочка в согласии при регистрации).
- **Роль школьного психолога** (опция): видит отчеты + selfdoubt-агрегаты, это ваш «пусковой крючок» для допродажи индивидуальных консультаций.

## 5. Кабинет консультанта (сердце гибридной модели)

- Очередь черновиков отчетов: карточка ученика → полный профиль по дням → черновик от ИИ → редактирование → «Утвердить и опубликовать».
- Красная зона: safety-флаги всплывают поверх всего, с уведомлением (SMS/WhatsApp консультанту).
- Норматив времени: цель — 20–30 минут работы консультанта на отчет (против нескольких часов ручной подготовки). Это и есть экономика масштабирования франшизы.
- Правки консультанта в черновиках сохраняются как обучающие пары (draft → final) — золотой датасет для будущего дообучения промпта.

## 6. ИИ-интеграция

- **Модель:** Claude API. Диалоги — быстрая модель (Haiku/Sonnet-класс), report_draft и day7_synthesis — старшая модель (качество синтеза критично).
- **Оценка стоимости на одного ученика** (порядок величин): 6 диалоговых дней × ~15 сообщений + 2 вызова синтеза/отчета ≈ 150–300 тенге на LLM + STT ~50–100 тенге. Итого себестоимость ИИ < 500 тг/ученик — при B2C-цене продукта в десятки тысяч тенге это ~1%.
- **STT:** Whisper API (казахский поддерживается) или Yandex SpeechKit; выбрать по качеству казахской транскрипции на пилоте — это надо тестировать на реальной подростковой речи (код-свитчинг «казахский+русский» в одной фразе — обязательный тест-кейс).
- **Версионирование промптов + eval:** каждый релиз промпта прогоняется на эталонных кейсах (Асылжан + 3 синтетических) с автоматическим сравнением report_draft. Без этого любая правка промпта — русская рулетка.

## 7. Соответствие законодательству РК

- Хранение персональных данных — на серверах в РК (закон «О персональных данных и их защите»). LLM-вызовы за рубеж: передавать только псевдонимизированные данные (без ФИО/телефона — ИИ они не нужны, в profile_json их просто нет).
- Согласие родителя/законного представителя на обработку данных несовершеннолетнего — обязательный шаг онбординга (электронная подпись/SMS-подтверждение с фиксацией).
- Трехстороннее соглашение для B2B (школа–родитель–платформа) с явным описанием: что видит школа, что не видит никто, кроме консультанта.
- Проконсультируйтесь с юристом по: порогу возраста самостоятельного согласия, регламенту действий при safety-флагах (ваш ручной протокол — правильный, но его стоит зафиксировать письменно), сроку хранения переписки.

## 8. Этапность (реалистичная)

| Этап | Что | Зачем |
|---|---|---|
| **0. Пилот-макет (2–3 недели)** | Опросники и свайпы на конструкторе (Tally/Typeform-класс) + чат-ИИ в виде отдельного простого веб-чата с вашим промптом + скоринг в таблицах. 5–10 детей | Проверить методику, промпт и вовлеченность ДО инвестиций в разработку |
| **1. MVP (6–10 недель)** | Полный путь подростка (7 дней, игра, чат, голос) + кабинет консультанта + оплата Kaspi + RU/KZ | Первые B2C-продажи |
| **2. B2B (4–6 недель)** | Кабинет школы, лицензии, агрегаты, роль психолога | Продажи школам |
| **3. Масштаб** | Взрослая версия («Глубина»), франчайзи-кабинеты, дообучение на датасете правок | Рост |

Этап 0 критичен: он проверит главный риск продукта (доходят ли дети до Дня 7 и честно ли отвечают ИИ) за копейки.

## Вопросы на валидацию

1. Кто будет разрабатывать: своя команда / подрядчик в КЗ / no-code+фрилансер? От этого зависит детализация ТЗ, которое я подготовлю следующим шагом.
2. Пилот (этап 0): согласны начать с макета на конструкторах? Могу следующим шагом собрать полный сценарий пилота (какие инструменты, что мерим, критерии успеха).
3. Норматив «20–30 минут консультанта на отчет» — реалистичен для вас как методолога? Это ключевая цифра юнит-экономики.
4. Агрегаты для школ с порогом анонимности 8 учеников — достаточно, или ваш опыт с школами требует другого?
